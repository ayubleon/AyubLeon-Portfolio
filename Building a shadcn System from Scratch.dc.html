Building a shadcn System from Scratch

A component framework built on shadcn/ui, originally a personal project, later adapted to power BuzzIQ. 2024 – Present.

Position

Systems Product Designer

Product

BuzzIQ

Overview

This started as a personal project, not a client one. The free shadcn resources on Figma Community were thin, promotional demos built to funnel people toward paid kits, and the paid kits were priced per seat in a way that didn't make sense for where I was at. I had the time and the curiosity, so I set out to rebuild the real, open-source shadcn/ui library properly in Figma myself, partly to understand how a design system like that actually works under the hood.

I landed the BuzzIQ role not long after finishing it, and the system I'd already built turned out to be exactly what that fast-moving project, with no existing design infrastructure of its own, needed.

Documentation Elements

30+ reusable components and 400+ variants, documented with spacing and text tokens as named styles. Every component is built and shown across both light and dark mode states, and the system standardizes on Lucide for icons and Sonner for toast notifications, both tools shadcn/ui itself is built around.

Design Process

I started by auditing shadcn's actual component states, then worked through each component and its variants one at a time, checking that they held up inside full interface layouts rather than just as isolated specs. That meant testing each piece the way it would actually get used, not building a reference sheet that looked clean in isolation but fell apart the moment it met a real screen.

Challenges

Navigating challenges & quality control

Adapting a system built for no specific product to a real one

The system wasn't originally built with BuzzIQ, or any single product, in mind. Once I brought it into a fast-moving project with real requirements, I had to adjust it for BuzzIQ's specific needs and build a handful of custom components and variant states it didn't originally cover. Most of the system held up as-is, but knowing where it needed to flex versus where it could be used directly was its own design decision.

Impact

Business & workflow impact

Because the foundation already existed, most of BuzzIQ moved faster than it would have starting from zero. The system's light and dark mode support, built in from day one rather than retrofitted, made designing both states across the product straightforward instead of a late addition.

And because it standardized on one icon set and one toast pattern from the start, developers didn't have to reconcile mismatched libraries the way they might have with an ad hoc component set.
